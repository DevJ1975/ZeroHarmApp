## Only you can do these (in order)

1. **Apple Developer Program** for Trainovate Technologies (needs the D-U-N-S number), then `npx eas-cli@latest init` and create the app record for `ai.trainovate.zeroharm`.
2. **Deploy the backend** on Railway: set `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`, `ONESIGNAL_APP_ID`, `ONESIGNAL_REST_API_KEY`, `GHL_PRIVATE_TOKEN`, `INGEST_KEY`, `BACKOFFICE_KEY` on web and cron, and `OWNER_ALERT_EMAIL` so reports, crashes and removal requests reach you. It must stay up through review. **Changing a variable restarts the service**, so set them when no Monday Minute safety test is running (see "Changing a Railway variable" in the README). After the deploy, do the caller address check in the README ("After a deploy: check the caller address").
3. **Give the build its OneSignal app id.** `eas.json` now sets the API, privacy, terms and support values for production. Still missing: `EXPO_PUBLIC_ONESIGNAL_APP_ID` (not in the repo). Add it to `build.production.env` in `eas.json` or as an EAS environment variable. Without it, pushes do not work in the store build.
4. **Lawyer review of the privacy policy and terms.** Both pages are live once the backend deploys (`/privacy/`, `/terms/`). The points to confirm are marked `[LAWYER REVIEW]` in HTML comments in `backend/legal/templates/legal/privacy.html` and `terms.html`: how long to keep sign-in sheets as training records, crew photo and signature consent, the state law section, which AI provider production uses (`AI_PROVIDER`), the access-log wording for weather (does Railway's edge log keep the query string?), crash reports on by default, how long to keep problem reports, warranty and liability wording, the $100 cap, Nevada venue and Apple's standard EULA terms. After any change, update `EFFECTIVE_DATE` / `LAST_UPDATED` in `backend/legal/views.py`. Enter the same URLs in App Store Connect.
5. **A support email** that someone reads daily. Apple expects comment reports to be acted on within 24 hours.
6. **Real content before review:** at least one approved Monday Minute (two or three is better), the text for Zero Harm Weekly issues 1 and 2, one alert and one Learn item. Empty screens are the most common rejection.
7. **Push:** upload an APNs key (.p8) to OneSignal and send a test push to a TestFlight build.
8. **App Store Connect listing:** 6.9-inch iPhone screenshots from the real build, description that says Monday Minute is AI-written and OTIS is an on-device AI assistant (no claim of OSHA compliance), support and privacy URLs, age rating with user-generated content declared, and the App Privacy answers below.
9. **Test on a real iPhone:** the OTIS download (0.5 to 1.3 GB) with the app in the background, crew sign-in, print and share, and the holiday opening screen. Also the new parts, which have only been checked by automated tests: "Report a problem" with and without signal, "My reports", "Report this answer" under an OTIS reply, the "Crash reports" switch, and the app's error screen.
10. **After approval:** set `APP_STORE_URL` (and `PLAY_STORE_URL` once Android is live) on the Railway web service. This restarts the web service, so first check that no Monday Minute safety test is running (see "Changing a Railway variable" in the README). The invite link sent from GoHighLevel (`/get/?c={{contact.id}}`) then sends phones straight to the store, with no app update. Until then it shows "Coming soon".

## Privacy policy checklist

Ticked items are covered by `backend/legal/templates/legal/privacy.html` (2026-11-13). The policy must say, in plain words, that the app collects or sends each of these, why, who handles it and how long it is kept.

- [x] Email, name and company from the optional sign-in, and the weekly newsletter they lead to.
- [x] Crew names, finger signatures and crew photos on a sign-in sheet, sent only when "Save sheet to my records" is tapped, and filed in GoHighLevel under the supervisor's email.
- [x] Comments, replies, ratings, talk ideas, and the display name shown with a comment.
- [x] The push token, and what OneSignal records by itself.
- [x] Approximate location for weather.
- [x] The random install id. The server keeps it only as a scrambled (hashed) form. When the person signs in, that scrambled id is kept with their name and email, so anything else stored under it (problem reports, flagged answers, votes, the usage count) can be matched to them. Crash reports use a different scrambled id that cannot be matched.
- [x] The anonymous daily usage count: once a day the app tells the server that a phone opened it, with the platform, app version and an approximate city, state and country. The place comes from the phone's approximate location when allowed, otherwise it is worked out from the network address, which is not stored. People can switch the count off in Settings. DB-IP is the source of the network place lookup.
- [x] **Crash reports.** When the app hits an error it sends the error, where in the app's code it happened, the screen, the time, the app version, the phone model and system version, and a scrambled id made for crash reports only. That id does not match the one kept with a sign-up or a problem report, so a crash report cannot be traced to a person. Never what the person typed, their name, email, photos, location or OTIS chat. On by default, with a switch in Settings; turning it off deletes reports waiting on the phone. Single crash reports, with the phone model and system version, are deleted after 90 days (`SUPPORT_CRASH_KEEP_DAYS`), and the crash ticket's copy of the first phone's model, system version and screen is cleared at the same age; the count of how often an error happened is kept.
- [x] **Problem reports (support tickets).** What the person writes, their email only if they give one for a reply, the language, the phone model, system version, app version and the install id. It can be linked to the person: it may hold their email, and its install id is the same one kept with a sign-up from that phone. Kept until deleted on request. The person can see the status and the reply in the app, under "My reports".
- [x] **A flagged OTIS answer.** "Report this answer" sends that one question and that one answer to Trainovate, after the person confirms, with the same phone facts and install id as a problem report, so it can be linked to a sign-up from that phone too. Nothing else from the chat is sent. It is not listed under "My reports", so the person never sees a reply to it.
- [x] **Tickets reach GoHighLevel.** Every problem report and flagged answer is emailed to Trainovate through GoHighLevel, and so is a summary of crashes. When the person gave an email for a reply, a GoHighLevel contact is made or updated for them with a tag and a note holding what they wrote.
- [x] **OTIS.** Questions stay on the phone unless the person chooses to send a problem report or flag an answer, or turns on "Help improve OTIS" with "Include my question".
- [x] **Hugging Face.** OTIS's model files download from Hugging Face (huggingface.co) unless a model release pinned in the admin points somewhere else. Hugging Face sees the phone's network address during the download, and the model library sends it one download-count request.
- [x] The companies that handle data for the app: OneSignal (push), GoHighLevel (contacts, email, saved sheets, tickets), Railway (hosting), Hugging Face (model download), DB-IP (the city database, which runs on our own server), and the AI that screens comments.
- [x] How long records are kept, and how to ask for deletion: "Remove my info" in the app, the "Delete my data" email, which now also names problem reports, and a public web page for people who no longer have the app.

## Notes for the reviewer (paste into App Store Connect)

- No account is needed. The first screen asks for a name and email for the free weekly newsletter. Tap "Not now" to skip it. Every feature works without signing in, and there is no password.
- A sign-up can be removed in the app, in Settings.
- Monday tab: this week's AI-written talk. Scroll down for thumbs, comments, Report and Block (the ••• on a comment) and the community rules shown before a first post. Comments are screened before they show, reports are acted on within 24 hours (the owner is emailed on the first report of each comment), and a poster can be stopped from commenting from the admin.
- Crew sign-in: Start crew sign-in, type a name, sign, optionally take a group photo, then Print or Share.
- OTIS: an AI assistant that runs on the phone. First use downloads a model over Wi-Fi. Questions stay on the phone unless you choose to send a problem report or flag an answer. Every answer has "Report this answer", which sends that one question and answer to us for review after a confirm.
- Problems with the app: Settings → Report a problem. The screen says exactly what is sent. Crash reports can be switched off in Settings → About and privacy.
- Notifications are off until turned on in Settings. "News and offers" is the only promotional one.
- The app gives general safety awareness. It is not legal, medical or compliance advice.

## Still open in code

- Removing a sign-up (name and email) in the app is done for the phone that signed up. From another phone it is a request the owner carries out by hand: delete the sign-up in the admin and take the newsletter tags off the contact in GoHighLevel. There is no one-click "carry out this removal" in the admin yet, and if `OWNER_ALERT_EMAIL` is blank nobody is told about the request.
- Still an email request: deleting your own comment, saved sign-in sheets and problem reports from the server. "Remove my info" does not touch problem reports. Deleting the GoHighLevel contact itself is also by hand (removal takes the tags off and marks it).
- Done: the two app lines that said OTIS questions never leave the phone now name the exceptions, matching the privacy policy. The OTIS set-up screen (`app/otis.tsx`): "What you ask stays on this phone unless you choose to report a problem or an answer, or turn on Include my question in Settings." Settings → OTIS (`app/settings.tsx`): "What you ask stays on it unless you turn this on, or you choose to report a problem or an answer."
- The "No" for crash data under App Privacy holds only once the server keeps crash reports under their own scrambled id and clears the first phone's details on a crash ticket after `SUPPORT_CRASH_KEEP_DAYS` (90 days). Both are in the code now (`crash_hash` in `backend/support/api.py`, and `support_prune`). Check that this is in the server you deploy before you send the form.
- Thumbs (votes) and the once-a-day app open count are stored under the same scrambled install id as a sign-up, so for anyone who signed in they can be matched to a name and email. The daily count's row also holds the city, state and country the phone was in that day. Until they get their own id in code, as crash reports have, answer "Yes" (linked to the person) for both Product interaction and Coarse location, as the table above does. Once they have their own id, both can go back to "No".
- The error screen, the report form and the crash reporter have not been seen on a phone, only in automated tests.
- Done: an email to `OWNER_ALERT_EMAIL` on the first report of each comment (audit item A2; the cron resends it if GoHighLevel was down), and a per-phone comment ban ("Hide and stop the poster from commenting" in the comment admin; delete the ban row to lift it).
- A reason picker on reports, a "Blocked people" list, and blocking agency words in display names (audit B6).
- The sign-in sheet note should say a contact record is created (audit E2). The privacy policy now says it, so the in-app wording can follow.
- Done: gunicorn's access log now drops the query string (`zeroharm/logs.py`), so the weather lat/lon and the invite contact id are not in our own log, and every rate limit keys the cache on a salted hash of the network (`zeroharm/net.py`, `talks/views.py`). The policy says so. Still to confirm: whether Railway's own edge request log keeps the full address with its query string. The policy hedges ("may still record") until that is known.
- Retention limits: the usage count (400 days) and single crash reports (90 days, `SUPPORT_CRASH_KEEP_DAYS`) have one. Sign-in sheet records, comments, votes, reports, problem reports, flagged OTIS answers, crash tickets (error text and count only), suggestions, OTIS ratings, invite taps, removal requests, and the GoHighLevel emails, contacts and notes made for them are kept until deleted on request, as the policy says.
- The line under Send on Report a problem and in OTIS (`whatIsSent` in `lib/support/flow.ts`) ends "Nothing else", but a report also carries the system version (shown inside the phone name only when known) and the language (en or es). The policy lists both. Add "the language" to that line, or stop sending it.
- There is no in-app way to delete a problem report or a flagged answer, and "Remove my info" does not touch them. Deletion is by email, with the ZH number from "My reports".
